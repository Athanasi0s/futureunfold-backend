# Tenant Dependencies & Secrets Inventory

**Canonical reference** for everything that must be provisioned, registered, or
copied when standing up a new tenant. `ONBOARDING_NEW_TENANT.md` is the step-by-
step runbook; this doc is the checklist it walks through.

Any new third-party service or env var **must** update this file **and** the
runbook **and** `scripts/provision_tenant.sh`.

---

## Backend secrets (`fly secrets set -a festapp-api-<slug>`)

| Key | Scope | What it is | Source |
|---|---|---|---|
| `DATABASE_URL` | per-tenant | Postgres connection string | Auto-set by `fly postgres attach` |
| `TENANT_KEY` | per-tenant | Tenant slug; drives seed folder selection. App refuses to boot without it. | Provisioning script (= slug arg) |
| `JWT_SECRET` | per-tenant | HMAC signing key; security isolation per tenant | Provisioning script (`openssl rand -hex 32`) |
| `EVENT_NAME` | per-tenant | Display name in emails, push, wallet passes | Customer-supplied |
| `ADMIN_EMAILS` | per-tenant | Comma-separated admin emails | Customer-supplied |
| `GOOGLE_CLIENT_ID` | per-tenant | Google Calendar OAuth. Redirect URI `https://festapp-api-<slug>.fly.dev/auth/google/redirect` — each tenant needs its own client | Manual: GCP Console |
| `GOOGLE_CLIENT_SECRET` | per-tenant | Paired with `GOOGLE_CLIENT_ID` | Same step as above |
| `GOOGLE_TOKEN_ENCRYPTION_KEY` | per-tenant | Server-side AES key for at-rest Google refresh tokens | Provisioning script (`openssl rand -hex 32`) |
| `STRIPE_SECRET_KEY` | per-tenant | Customer's own Stripe account | Customer-supplied |
| `STRIPE_WEBHOOK_SECRET` | per-tenant | Paired with `STRIPE_SECRET_KEY`; webhook URL differs per tenant | Customer-supplied (from their Stripe dashboard) |
| `SENDGRID_API_KEY` | **shared** | Single Sendgrid account | Set once across all tenants |
| `SENDGRID_FROM_EMAIL` | per-tenant | Brand identity in outgoing email | Customer-supplied (requires Sendgrid domain verification) |
| `GOOGLE_WALLET_ISSUER_ID` | **shared** | Single Wallet issuer | Set once across all tenants |
| `GOOGLE_WALLET_CLASS_SUFFIX` | per-tenant | e.g. `<slug>_badge`; prevents "already added" collisions | Provisioning script or manual |
| `GOOGLE_WALLET_TICKET_CLASS_SUFFIX` | per-tenant | e.g. `<slug>_ticket` | Provisioning script or manual |
| `GOOGLE_WALLET_SA_JSON_B64` | **shared** | Service account for the shared issuer; base64 JSON | Set once across all tenants |
| `GOOGLE_WALLET_ORIGIN` | per-tenant | Matches tenant API URL | Derived: `https://festapp-api-<slug>.fly.dev` |
| `SKIP_SEEDS` | per-tenant (optional) | Escape hatch to bypass bootstrap on emergency redeploy | Unset by default |

## Backend infrastructure (Fly.io)

| Resource | Scope | Notes |
|---|---|---|
| Fly app `festapp-api-<slug>` | per-tenant | `fly apps create` |
| Fly Postgres cluster `festapp-api-<slug>-db` | per-tenant | 3GB default; size up at launch if >10k users expected |
| Fly volume `uploads_data` | per-tenant | 3GB default; user-uploaded files (avatars, certificates) |
| `fly.<slug>.toml` | per-tenant | Generated by `scripts/provision_tenant.sh` from `fly.panathenea.toml` |
| Entry in `tenants.yml` | per-tenant | Appended by provisioning script; drives CI matrix |
| Per-tenant seed folder `app/seed/tenants/<slug>/` | per-tenant | Scaffolded empty (`ordered_seeds = []`); populated when event-specific data lands |

## Mobile per-tenant config (`festapp-mobile/app.config.ts` tenant map)

| Field | Scope | What it is | Source |
|---|---|---|---|
| `name`, `slug`, `scheme` | per-tenant | Expo identifiers + deep-link scheme | Derived from slug + customer name |
| `ios.bundleIdentifier` | per-tenant | `com.festapp.<slug>` | Auto-derived |
| `android.package` | per-tenant | `com.festapp.<slug>` (new tenants); Panathenea exception: `com.festapp.festapp` | Auto-derived |
| `ios.buildNumber` / `android.versionCode` | per-tenant | Starts at 1 for new tenants | Manual |
| `apiBaseUrl` | per-tenant | `https://festapp-api-<slug>.fly.dev` | Auto-derived |
| `tenantKey` | per-tenant | Passed to app via `extra`; informational | = slug |
| `easProjectId` | per-tenant | **Expo enforces 1:1 slug/projectId.** Each tenant needs its own Expo project. | Manual: create at expo.dev → Projects, copy UUID |
| `owner` (Expo org) | **shared** | Top-level `owner: "feststats"` in ExpoConfig. Required for org-owned projects. | Set once at top level |
| `easChannel` | per-tenant | `<slug>-production` for OTA isolation; Panathenea stays `production` for backward compat | Derived |
| Android keystore | per-tenant | EAS generates on first Android build. **Back up via `eas credentials`** after first build. | Auto-generated |

## EAS dashboard env vars (per-tenant, set at expo.dev)

Separate from the `env` block in `eas.json`. Consumed by `eas submit`,
`eas update` (OTA), and any build not overriding via profile env.

Mark Google OAuth + Mapbox tokens as **Secret** in the dashboard.

| Var | Scope | Same as Panathenea? | Notes |
|---|---|---|---|
| `APPLE_API_ISSUER_ID` | **shared** | Yes | Copy from Panathenea project |
| `APPLE_API_KEY_ID` | **shared** | Yes | Same |
| `APPLE_API_KEY_PATH` | **shared** | Yes | Same `.p8` file path |
| `EXPO_PUBLIC_API_BASE_URL` | per-tenant | **Different** | `https://festapp-api-<slug>.fly.dev` — required for OTA to target the right backend |
| `EXPO_PUBLIC_MAPBOX_TOKEN` | **shared (for now)** | Yes | One Mapbox account; split later if billing splits needed |
| `EXPO_PUBLIC_GOOGLE_CLIENT_ID` | per-tenant | **Different** | Only if Google Calendar enabled. New OAuth web client with redirect to tenant's backend |
| `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID` | per-tenant | **Different** | Tied to `com.festapp.<slug>` + keystore SHA-1 (create after first Android build so SHA-1 is known) |
| `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | per-tenant | **Different** | Tied to `com.festapp.<slug>` iOS bundleId |

**Blocking timeline:**

| Milestone | Required env vars in EAS dashboard |
|---|---|
| First dev-client smoke build | None (`eas.json` env block supplies what's needed) |
| First OTA update (`eas update`) | `EXPO_PUBLIC_API_BASE_URL` |
| First `eas submit` to TestFlight / Play internal | `APPLE_*` trio |
| Google Calendar feature in the new tenant's app | `EXPO_PUBLIC_GOOGLE_*` trio |

## Platform / account registrations (manual, one-time per tenant)

| Step | Scope | Where | Notes |
|---|---|---|---|
| Apple App Store Connect app record | per-tenant | App Store Connect | Same Apple Developer team; new app with tenant's bundleId |
| Google Play Console app record | per-tenant | Play Console | Same Google Play account; new app with tenant's package |
| Firebase project | per-tenant | Firebase console | Required for push. Register both iOS + Android apps; download both config files |
| Google Cloud OAuth clients | per-tenant | GCP → APIs & Services → Credentials | 4 clients per tenant: Web (backend), Web (mobile EXPO_PUBLIC), Android, iOS |
| Google Wallet class registration | per-tenant | `py -m scripts.register_wallet_classes --kind both` | Creates `<slug>_badge` + `<slug>_ticket` classes under shared issuer |
| Stripe account connection | per-tenant | Customer's Stripe dashboard | Customer creates webhook pointed at `https://festapp-api-<slug>.fly.dev/webhooks/stripe`; hands you the signing secret |
| Sendgrid sender domain verification | per-tenant | Sendgrid → Sender Authentication | Only if using tenant-specific from-email domain |
| Mapbox style (optional) | per-tenant | Mapbox Studio | Only if customer wants custom-branded map |
